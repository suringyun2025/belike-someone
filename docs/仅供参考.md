# 人物能力蒸馏与通用 Agent Skills 工作台：开发方案

> 版本：1.0.0｜状态：技术评审与开发交付版｜产品形态：本地优先 Web
> UI，可选 Docker 部署

## 1. 项目目标与边界

开发一套具有可视化 UI
的应用，将经授权的人物资料蒸馏为可审计、可测试、可导出的通用 Agent
Skills 包。它不是单纯的人设提示词生成器，而是从大规模异构资料中提取：

-   **专业能力**：知识领域、方法论、工作流、工具使用方式、质量标准。
-   **思维与决策模式**：分析框架、判断条件、权衡因素、风险和例外。
-   **人格与表达风格**：资料有依据的沟通习惯、语气、措辞和互动边界。
-   **知识与案例**：事实、术语、作品、案例及原始来源。
-   **可执行 Skills**：标准化 `SKILL.md`、参考资料、评估用例和可选脚本。
-   **审计材料**：证据、推断等级、冲突记录、人工审核、测试结果和版本差异。

原则：证据优先、能力优先于模仿、人格与知识分离、小而可调用、人工可控、本地优先、安全默认。不得把模型推断写成当事人明确表达的事实；不得暗示输出由真实人物亲自撰写或认可。现实人物资料应具有适当授权或合法来源；不应推断或输出不必要的敏感个人属性。

### 非目标

首版不训练基础模型，不承诺还原真实意识或完整人格，不自动冒充本人发言，不绕过访问权限，不执行资料中嵌入的命令，也不保证所有
Agent 平台的运行行为完全一致。

## 3. 产品工作流与 UI

### 3.1 主要工作流

1.  创建人物项目，填写人物代号、目标能力、用途、授权/来源备注和禁止用途。
2.  批量导入访谈、文章、课程转录、聊天记录、代码/文档、案例。
3.  查看解析状态、重复文件、敏感信息提示和来源元数据。
4.  配置 LLM 协议、供应商、模型和参数，测试连接。
5.  定义人物能力地图：专业能力、决策模式、表达风格、知识资料。
6.  启动蒸馏；查看阶段进度、暂停、恢复、重试、取消。
7.  审核事实、推断、矛盾、低置信度规则和引用来源。
8.  生成原子化 Skills，执行结构验证、隐私扫描和行为评估。
9.  查看版本差异，人工批准后导出 ZIP 或目录。

### 3.2 左侧导航

-   **仪表盘**：项目、资料、待审核项、运行任务、失败任务、Token/费用估算。
-   **人物项目**：创建、复制、归档、项目配置导入/导出。
-   **资料库**：上传、目录导入、预览、去重、脱敏、排除、重新解析。
-   **人物画像**：能力地图、决策规则、表达风格、事实/推断分栏。
-   **蒸馏流水线**：阶段、输入/输出、日志、失败重试、暂停/恢复。
-   **模型与 API**：协议、Base URL、密钥、模型 ID、参数、连通性测试。
-   **Skills 工作台**：列表、编辑器、引用证据、资源、版本和质量报告。
-   **评估中心**：测试集、基线、运行结果、失败案例、回归测试。
-   **导出与兼容性**：ZIP/目录、目标平台说明、结构检查。
-   **设置**：数据目录、并发、缓存、日志、脱敏、备份和访问控制。

所有长任务应显示阶段、已处理/总量、当前文件、耗时、费用估算和最近错误。危险操作（删除源资料、覆盖
Skill、永久删除项目）必须确认。API Key
掩码显示，刷新页面不得返回明文密钥。

## 4. 三种 LLM API 协议

首版支持三个独立适配器，不可用同一个请求体强套所有供应商。

### A. OpenAI-compatible Chat Completions

字段：协议、显示名称、Base URL、API Key、Model
ID、超时、重试、流式开关、`temperature`、`top_p`、输出 Token
上限、`frequency_penalty`、`presence_penalty`、`stop`、JSON
输出模式、自定义请求头和附加 JSON 字段。

适用于 OpenAI Chat Completions
形态及明确兼容的供应商。不能假定所有兼容端点都支持所有参数；不支持的参数必须警告或按设置忽略。

### B. Anthropic Messages

字段：Base URL、API Key、Model
ID、`anthropic-version`、`max_tokens`、`temperature`、`top_p`、可选
`top_k`、`stop_sequences`、流式开关、超时、重试和高级附加参数。适配器负责映射
`system`、`messages`、内容块和流式事件。

### C. Google Gemini `generateContent`

字段：Base URL、API Key、Model
ID、`temperature`、`topP`、`topK`、`maxOutputTokens`、`stopSequences`、JSON
模式、安全设置、流式开关、超时、重试和高级附加参数。适配器负责映射
`contents`、`parts`、`systemInstruction`、`generationConfig`、`candidates`
和 finish reason。

### 4.1 统一内部请求/响应

``` json
{
  "system": "阶段级系统指令",
  "messages": [{"role": "user", "content": "待处理内容"}],
  "generation": {
    "temperature": 0.2,
    "top_p": 0.9,
    "max_output_tokens": 4096,
    "stream": false,
    "response_mode": "json"
  },
  "metadata": {"project_id": "p1", "job_id": "j1", "stage": "extract"}
}
```

内部响应统一为 `text`、可选
`json`、`finish_reason`、`usage`、`request_id` 和
`warnings`。供应商未返回 Token 用量时保存
`null`，不得编造精确数字；成本只能标记为估算。

### 4.2 模型参数 UI 与行为

每个 Provider
页面分为连接信息、常用参数、高级参数。必须支持多个配置、复制配置、恢复默认、测试连接、测试
JSON 输出、查看最近错误；每个蒸馏阶段可单独指定 Provider/Model
和参数。项目级参数可覆盖全局默认。任务开始时保存完整参数快照。

连接测试必须实际发送小型请求。统一错误码至少包含
`AUTH_ERROR`、`PERMISSION_ERROR`、`MODEL_NOT_FOUND`、`RATE_LIMITED`、`QUOTA_EXCEEDED`、`TIMEOUT`、`NETWORK_ERROR`、`INVALID_REQUEST`、`PROVIDER_ERROR`、`INVALID_RESPONSE`、`CONTENT_FILTERED`。日志只记录脱敏摘要、HTTP
状态、耗时和 request ID，不记录密钥或完整私密提示词。

官方协议参考：[OpenAI
API](https://developers.openai.com/api/reference/overview)、[Anthropic
Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini
generateContent](https://ai.google.dev/api/generate-content)。

## 5. 人物模型、证据与资料

### 5.1 五个维度

1.  专业能力。
2.  思维/决策模式。
3.  人格/表达风格。
4.  知识与案例。
5.  证据、不确定性和冲突。

### 5.2 证据标签

-   `direct_quote`：可定位的直接陈述。
-   `repeated_pattern`：多个独立样本反复出现的模式。
-   `validated_workflow`：真实操作、作品、测试或结果支持的流程。
-   `model_inference`：模型推断，未由来源直接证实。
-   `human_verified`：人工审核通过。
-   `contradicted`：与其他证据冲突。
-   `rejected`：人工驳回，不进入最终 Skill。

置信度仅用于排序审核优先级，不代表客观真值。UI
必须显示来源数量、类型、位置和审核状态。

### 5.3 首版支持输入

`.md`、`.txt`、`.pdf`、`.docx`、`.html`、`.json`、`.jsonl`、`.csv`、`.xlsx`；可导入
ZIP，但必须防止路径穿越和压缩炸弹。后续可扩展 Git
快照、字幕、音频转录和授权网页。扫描 PDF 的 OCR
应作为可选能力，不得暗中上传第三方。

每个 Source
记录原始名称、大小、MIME、SHA-256、导入时间、来源/授权备注、语言、解析器版本、解析状态、脱敏状态。相同哈希文件标记为重复但不自动删除；相似文本仅提供合并建议。原始资料只读保存，派生文本分开存放。

## 6. 蒸馏流水线

### 6.1 阶段

1.  项目定义和授权备注。
2.  批量导入、格式检查、哈希和安全检查。
3.  文本解析，保留标题、页码、表格、代码块和源位置。
4.  规范化与脱敏。
5.  分块与索引，保留源文件、页码/标题/行号和块 ID。
6.  生成资料地图：主题、术语、时间线、覆盖盲区。
7.  分维度提取：专业技能、工作流、决策规则、人格/表达、案例和事实。
8.  将每个候选关联到一个或多个证据片段。
9.  冲突检测：记录上下文、时间变化、矛盾来源。
10. 归纳成原子化能力单元。
11. 编译 `SKILL.md`、references、evals 和必要资源。
12. 静态验证：元数据、链接、秘密、路径、依赖、引用长度。
13. 行为评估：触发、忠实度、边界、隐私和泛化。
14. 人工审核低置信度、高风险、矛盾和人格推断。
15. 生成版本、清单和导出包。

### 6.2 断点续跑

任务状态：`queued`、`running`、`waiting_for_review`、`paused`、`retrying`、`completed`、`failed`、`cancelled`。每阶段保存输入哈希、输出文件、流水线版本、提示词版本、模型参数快照、耗时、用量、成本估算、错误和重试次数。相同输入哈希与版本可复用已有结果；资料或提示词变化只使相关下游阶段失效。取消任务不删除已完成结果。写文件使用临时目录和原子重命名。

### 6.3 大规模处理

-   解析与 LLM 调用分离；并发受供应商限流控制。
-   使用 Map/Reduce 或主题聚类，但所有结论必须可追溯到原始证据。
-   设置项目预算、阶段 Token 上限、最大调用数和并发数。
-   允许用户指定资料优先级；重复/低价值资料延后。
-   缓存键包含输入哈希、提示词版本、模型 ID、参数快照和流水线版本。
-   429/5xx/网络错误采用指数退避和随机抖动；认证、模型不存在和参数错误不盲目重试。
-   每批次记录成功、跳过和失败清单。

### 6.4 质量门禁

出现以下情况时阻止自动导出或要求审核：没有触发条件；关键规则无来源且未标注推断；引用缺失/失效；检测到密钥或私人信息；依赖未声明工具；缺少
evals；关键事实冲突未处理；输出包含过长原文；目录不符合目标规范。

## 7. Skills 与人物包输出

### 7.1 单个 Skill 结构

``` text
<skill-name>/
├── SKILL.md
├── references/
│   ├── methodology.md
│   └── examples.md
├── evals/
│   ├── evals.json
│   └── results-summary.md
└── assets/  # 仅在必要时
```

仅当确有必要且经安全审核时才生成
`scripts/`；默认不执行任何源资料中的脚本。

### 7.2 `SKILL.md` 模板

``` markdown
---
name: architecture-decision-review
description: 用于评估计算机体系结构方案，在性能、功耗、面积、成本和复杂度之间进行可追溯权衡。仅在用户要求比较架构方案或审查架构决策时触发。
---

# 架构决策审查

## 目标
描述任务和预期输出。

## 适用条件
列出触发条件、必要输入和不适用场景。

## 输入
问题定义、约束、候选方案、可用测量数据。

## 执行流程
1. 明确目标与硬约束。
2. 标记未知信息，必要时先提问。
3. 逐项比较候选方案。
4. 记录权衡、风险和反例。
5. 给出结论、置信度与验证计划。

## 质量标准
列出必须检查的项目和完成条件。

## 失败处理
说明信息不足、证据冲突或工具不可用时如何停止/降级。

## 来源与限制
引用随附 references，区分资料支持的规则与归纳结果。
```

这是结构示例，不代表任何真实人物的观点。实际规则必须由证据生成。

### 7.3 完整人物模型包

``` text
person-model-package/
├── manifest.json
├── README.md
├── persona/
│   ├── persona.md
│   ├── communication-style.md
│   └── interaction-boundaries.md
├── decision-model/
│   ├── decision-rules.md
│   └── uncertainty-and-contradictions.md
├── skills/
│   └── <skill-name>/
│       ├── SKILL.md
│       ├── references/
│       └── evals/
├── knowledge/
│   ├── index.md
│   └── glossary.md
├── provenance/
│   ├── source-manifest.json
│   ├── evidence-summary.md
│   └── review-log.json
├── evaluations/
│   ├── benchmark.json
│   └── final-report.md
└── compatibility/
    ├── agentskills.md
    └── platform-notes.md
```

完整人物包是本应用的扩展打包格式；真正可移植的核心单元是每个
`skills/<name>/`
目录。不同运行时对人格文件和知识库的加载方式不同，必须在 README
中说明手动导入或平台适配步骤。

`manifest.json` 包含 package 名称/版本、创建时间、流水线版本、Skill
列表及哈希、脱敏来源
ID/哈希/许可备注、人工审核状态、评估结果、目标格式和限制。不包含 API
Key、Cookie 或私人聊天全文。

## 8. 技术架构

### 8.1 技术栈

-   前端：React + TypeScript + Vite；UI 组件库可选 shadcn/ui
    或同类方案。
-   后端：Python 3.11+、FastAPI、Pydantic。
-   HTTP：`httpx`；每个协议独立 Adapter。
-   数据库：SQLAlchemy 2.x；本地 SQLite，规模扩大后可切 PostgreSQL。
-   后台任务：首版使用持久化 Job 表 + 独立 Worker；高并发部署时可引入
    Redis/Celery。
-   文件存储：本地文件系统，数据库记录元数据。
-   测试：pytest、前端测试、协议 mock server、Playwright。
-   部署：本地 Python + Node 开发；稳定后提供 Docker Compose。

### 8.2 组件边界

``` text
React UI ─ REST/SSE ─ FastAPI
                      ├─ Project/Source Service
                      ├─ Parser/Normalizer/Redactor
                      ├─ Distillation Orchestrator
                      │   ├─ Evidence Extractor
                      │   ├─ Conflict Resolver
                      │   ├─ Skill Compiler
                      │   └─ Evaluation Runner
                      ├─ LLM Adapter Registry
                      │   ├─ OpenAI-compatible
                      │   ├─ Anthropic Messages
                      │   └─ Gemini generateContent
                      ├─ Job/Checkpoint Service
                      └─ Export/Compatibility Service
                            ├─ SQLite/PostgreSQL
                            └─ Local Artifact Store
```

前端不直接调用模型供应商。Adapter
只返回规范化结果，不直接写项目文件。LLM 输出先做 Pydantic/JSON Schema
校验。Worker 与 HTTP 请求生命周期分离，关闭浏览器后任务可继续。默认监听
`127.0.0.1`。导出先写临时目录，验证通过后原子重命名。

## 9. 数据模型

建议至少包含：

-   `projects`：人物代号、目标能力、用途、授权备注、状态。
-   `sources`：原始名、路径、SHA-256、MIME、大小、来源/许可、解析/脱敏状态。
-   `source_chunks`：来源
    ID、分块序号、文本路径、页码/标题/行号、哈希、Token 估算。
-   `claims`：维度、结论、证据等级、置信度、冲突组、审核状态。
-   `evidence_items`：结论 ID、来源块 ID、短引文、证据类型、审核备注。
-   `provider_configs`：协议、Base URL、Model
    ID、加密密钥、参数和能力配置。
-   `jobs`：任务类型、状态、进度、当前阶段、输入哈希、流水线版本和错误。
-   `job_stage_runs`：阶段状态、输入/输出、Provider
    参数快照、用量、成本估算、重试次数。
-   `skills`：名称、版本、路径、哈希、状态、质量报告。
-   `eval_runs`：数据集、模型配置快照、指标、状态和报告路径。
-   `audit_events`：操作者、操作、目标和脱敏详情。

外键与常用查询字段建索引。删除项目采用软删除与显式永久删除；永久删除前确认并清理关联文件、缓存和派生结果。

## 10. API 草案

统一前缀 `/api/v1`。错误结构：

``` json
{"error":{"code":"INVALID_REQUEST","message":"参数不符合所选协议","request_id":"req_xxx","details":{}}}
```

接口至少包括：

-   `GET /health`
-   `GET/POST /projects`、`GET/PATCH/DELETE /projects/{id}`
-   `POST /projects/{id}/sources`、`GET /projects/{id}/sources`
-   `POST /sources/{id}/parse`、`POST /sources/{id}/redact-preview`
-   `GET/POST /providers`、`PATCH/DELETE /providers/{id}`、`POST /providers/{id}/test`
-   `POST /projects/{id}/distill-jobs`
-   `GET /jobs/{id}`、`POST /jobs/{id}/pause|resume|retry|cancel`
-   `GET /jobs/{id}/events`（SSE）
-   `GET /projects/{id}/claims`、`PATCH /claims/{id}`
-   `GET/POST /projects/{id}/skills`、`GET/PATCH /skills/{id}`
-   `POST /skills/{id}/validate`、`POST /skills/{id}/evaluate`
-   `GET /skills/{id}/versions`
-   `POST /projects/{id}/export`、`GET /exports/{id}`
-   `GET/PATCH /settings`

上传接口限制单文件大小、总项目容量、文件数和解压后大小。SSE
断开后，客户端可通过 GET 恢复状态。

## 12. 安全、隐私与版权

-   API Key 只在后端保存，使用 Windows 凭据库/DPAPI
    或跨平台密钥库；前端仅显示已配置状态和掩码。
-   不将密钥写入日志、错误栈、导出包、浏览器 localStorage 或参数快照。
-   把导入资料视为不可信内容；文档里的提示注入不能覆盖系统指令或触发工具执行。
-   解析器不得执行 Office 宏、脚本、嵌入式可执行文件或压缩包命令。
-   防止路径穿越、符号链接越权、超大文件、Zip bomb 和恶意 HTML/PDF。
-   提供脱敏预览和手动修正；自动脱敏不是绝对保证。
-   用户可以排除资料/片段，并让相关下游结果失效。
-   不将受版权保护的长篇原文复制到
    Skill；以方法归纳、必要短引用和来源说明为主。
-   对外发布时避免让受众误认为输出由本人亲自撰写或背书。
-   提供保留期限、源文件删除和派生缓存清理选项。

## 13. 测试与验收标准

### 13.1 三种协议

-   [ ] 三种协议分别通过 mock server 自动化测试。
-   [ ] OpenAI-compatible、Anthropic Messages、Gemini `generateContent`
    的请求体和响应解析正确。
-   [ ] 流式/非流式均可工作，流中断可安全恢复或重试。
-   [ ] 错误状态映射为统一错误码。
-   [ ] 无效密钥、无效模型、限流、超时、5xx、错误 JSON 均有测试。
-   [ ] 不支持参数会提示，不会静默假装生效。
-   [ ] 每阶段可选择 Provider/Model，任务记录参数快照。
-   [ ] 日志和前端不泄露密钥。

### 13.2 资料和蒸馏质量

-   [ ] 所有支持格式可导入和预览；不支持格式给出明确错误。
-   [ ] 相同哈希文件被识别为重复且不静默删除。
-   [ ] 结论能追溯到文件和页码/标题/行号（源格式允许时）。
-   [ ] 损坏文件隔离，不阻塞整批处理。
-   [ ] 测试用假密钥、邮箱和 Token 模式可被扫描。
-   [ ] Zip 路径穿越、压缩炸弹、超大文件被拒绝。
-   [ ] 被排除资料不会进入后续 LLM 请求。
-   [ ] 高优先级结论至少关联一个可定位证据；推断与直接事实分开。
-   [ ] 冲突信息保留来源与上下文，不被强制平均。
-   [ ] 每个 Skill 有触发条件、输入、步骤、输出、质量标准、失败处理。
-   [ ] 每个 Skill 至少 3 个正向测试、2 个边界/负向测试。
-   [ ] 对比无 Skill 基线与启用 Skill 的表现，报告改善和退化。
-   [ ] 低置信度、高风险、冲突或隐私风险内容可阻止自动导出。

### 13.3 导出与可靠性

-   [ ] 可导出完整人物包 ZIP 和普通目录。
-   [ ] 每个 Skill 含有效 `SKILL.md`，引用路径存在。
-   [ ] 导出不包含 API Key、Cookie、内部绝对路径和未审核私人资料。
-   [ ] 干净目录中无需本应用也能读取和使用核心 Skill。
-   [ ] 至少对两个 Agent Skills
    运行时做实际安装/调用测试；只做静态检查时必须标明未验证运行时行为。
-   [ ] Worker 重启后可从最近 checkpoint 恢复。
-   [ ] 重试不重复写入 Skill 或版本。
-   [ ] 暂停、恢复、取消和预算中止行为正确。
-   [ ] 导出失败不会破坏上一份成功导出。
-   [ ] 依赖锁定，完成安全扫描。

### 13.4 性能基准

至少测量 100 / 1,000 / 10,000 文件的导入吞吐、解析成功率、1/3/5
并发下的模型调用失败率、恢复耗时、UI
搜索响应、内存与磁盘增长。未固定机器、文件规模、网络和模型前，不承诺绝对吞吐数值；基准报告必须记录测试环境和参数。
